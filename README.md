# Kaplansky22 — collaborative search

[![Verify](https://github.com/Maksonch11k/kaplansky22-collab/actions/workflows/verify.yml/badge.svg)](https://github.com/Maksonch11k/kaplansky22-collab/actions/workflows/verify.yml)

**Совместный поиск конструкций 22×22 для гипотезы Капланского о делителях нуля. Контрпример пока не найден.**

Здесь можно подключить своего агента, улучшать модели поиска и добавлять новые доказанные запреты через pull request. Регистрация агента и передача ключей не нужны: сделайте fork, запустите своего агента у себя и предложите изменения.

**Collaborative 22×22 search towards Kaplansky's zero-divisor conjecture. No counterexample has been found.** Humans and agents contribute through ordinary forks, issues and pull requests. [English overview](README.en.md).

## Что уже доступно

| Компонент | Содержание |
|---|---|
| Два фиксированных семейства | `parallel22` и `trinomial22`, с точным порядком 22 левых и 22 правых образов |
| 532 запрета с сертификатами | 235 + 297; проверяются заново, а не принимаются по доверию к модели |
| Независимый проверяющий модуль | Только Python 3.11+, без GAP, Kaggle и ML-библиотек |
| Cross-entropy | Запускаемый табличный генератор спариваний, обучение, независимый случайный контроль |
| ML + SAT | SAT-генератор, ExtraTrees из 400 деревьев, 155 признаков, обучение и ранжирование |
| Данные обучения | 681 исторический пример; точная семантика метки и архитектура в [MODELS.md](docs/MODELS.md) |
| Совместная работа | Инструкции для агентов, шаблоны задач и PR, автоматические проверки |

## Начать за минуту

```bash
git clone https://github.com/Maksonch11k/kaplansky22-collab.git
cd kaplansky22-collab
python -m k22 verify --data data
python -m unittest discover -s tests
```

Для проверки сертификатов хватает стандартного Python. Для запуска CEM тоже не нужны дополнительные библиотеки:

```bash
python -m models.cem --family trinomial22 --epochs 10 --population 128 --output runs/cem-demo
```

ML и SAT устанавливаются отдельно:

```bash
python -m pip install -e ".[ml]"
python -m models.mlsat train --output runs/ml-baseline
python -m models.mlsat generate --family parallel22 --count 4 --output runs/sat-demo
```

Это короткие демонстрационные запуски. Генераторы выдают **непроверенные кандидаты**. Полный исторический алгоритм поиска доказательств не включён: для новых запретов нужен отдельный proof-producing checker и сертификат в формате проекта.

## Как присоединиться

1. Выберите или создайте задачу в [Issues](https://github.com/Maksonch11k/kaplansky22-collab/issues). Для идеи без готового доказательства достаточно issue.
2. Сделайте fork. Дайте своему агенту [AGENTS.md](AGENTS.md), [CONTRIBUTING.md](CONTRIBUTING.md) и выбранную задачу.
3. Добавьте сертификат, эксперимент или улучшение кода в своей ветке и откройте pull request. Новые запреты должны пройти независимую проверку; изменение проверяющего модуля требует отдельного внимания рецензента.

Пример задания агенту:

> Прочитай AGENTS.md и docs/MODELS.md. Улучши выбор пар в CEM. Сравни с текущей моделью и независимым случайным контролем при одинаковом бюджете, сохрани seed и хеши входов. Не называй обход известных запретов доказательством отсутствия кручения. Подготовь PR с кодом и воспроизводимым отчётом.

Формат доказательства и добавление запрета описаны в [CONTRIBUTING.md](CONTRIBUTING.md). Архитектура и точки расширения моделей — в [docs/MODELS.md](docs/MODELS.md).

## Что именно означает «запрет»

В каждом семействе фиксированы упорядоченные аффинные образы элементов. Спаривание всех 484 клеток задаёт 242 равенства произведений. Сертификат выводит из некоторых этих равенств соотношение `w^q = 1`; фиксированный образ слова доказывает `w != 1`. Поэтому исходная заданная группа содержит кручение.

Ядро запрета перечисляет нужные **необязательные** пары; остальные используемые пары принудительны в этом семействе. Любое полное спаривание того же семейства, включающее ядро, наследует доказательство кручения. Запрет нельзя переносить на другой порядок носителей или другое семейство без нового обоснования.

Это исключает такую исходную группу из поиска группы без кручения. **Само по себе это не исключает все её факторгруппы без кручения.** Отсутствие известных запретов и ответ `UNKNOWN` также не доказывают отсутствие кручения. Нужны отдельные доказательства отсутствия кручения и ненулевых множителей.
